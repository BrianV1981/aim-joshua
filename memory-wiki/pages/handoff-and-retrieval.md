# Handoff & Retrieval Protocols

## The Handoff Pipeline & Memory State Exemption
Agent Memory (`memory-wiki/**` and `HANDOFF.md`) is treated as living OS memory state rather than application code, explicitly exempt from GitHub Issues and `workspace/issue-*` worktrees:
1. **Mid-Session Checkpoint (`aim-memory-wiki`):** Can be run autonomously mid-session as a ~15-second "Save Game" that updates `memory-wiki/index.md`, `memory-wiki/log.md`, and `memory-wiki/pages/*.md`, runs `./aim index` if LanceDB is active, and pushes directly to `origin/main` (`git add memory-wiki/`, commit, `git pull --rebase --autostash origin main`, `git push origin main`) with zero prompts and without ending the session.
2. **One-Command Session Closeout (`aim-handoff`):** When ending a session, `aim-handoff` executes an **Idempotent Auto-Wiki Delta Check** first (inspecting `memory-wiki/log.md` and automatically updating `memory-wiki/` if unlogged session work occurred), surgically updates `HANDOFF.md` (`0–9` template), and pushes both `memory-wiki/` and `HANDOFF.md` directly to `origin/main` in a single atomic commit (`git add memory-wiki/ HANDOFF.md`, commit, `git pull --rebase --autostash origin main`, `git push origin main`) with zero confirmation prompts.
3. **Blackbox Vault & `/aim-sessions` Notebook ([Blackbox Vault](blackbox-vault.md)):** Before exiting the current session, the agent MUST seal the session into the immutable, Operator-locked blackbox vault (`aim agy-blackbox --session-id <uuid>`, `aim grok-blackbox`, etc.), resolving Antigravity 2.0 (`~/.gemini/antigravity/brain`) and legacy CLI (`~/.gemini/antigravity-cli/brain`) transcripts automatically and exiting `1` on failure (`#119`). Sealing simultaneously indexes a Markdown Flight Record into `<project>/joshua_os/archive/history.db` (SQLite FTS5) for unlimited project-scoped `/aim-sessions` (`./aim sessions`, `./aim search-sessions` with `_sanitize_fts5_query()` safe quoting for hyphens, dots, and `#`, `#124`) recall. Automated headless LLM pipelines (`reasoning_utils.py`) pass `--project ephemeral-pipeline` and invoke `cleanup_ephemeral_agy_sessions()` in `finally` blocks so background jobs never pollute interactive session history. Operators can diagnose vault keys (`keyring` + `~/.aim/blackbox.key`) via `aim vault doctor`.
4. **Baton Pass (Tier 2 POSIX Optional):** On POSIX hosts (`tmux` on Linux, WSL, macOS), the agent optionally spawns the next agent vessel and injects `HANDOFF.md` directly into its prompt; on native Windows 10/11 (Tier 1), continuity completes via the committed `HANDOFF.md` + `memory-wiki/` state and sealed Blackbox Vault.

## LanceDB Retrieval (Two-Tier Protocol)
A.I.M. uses LanceDB for semantic hybrid retrieval (RAG 5.21). When an agent needs to retrieve factual knowledge, it must natively act as a retrieval agent using the Two-Tier Protocol (see [Architecture](architecture.md)):
1. **Primary (Native Multi-Harness MCP — Pure Automatic Mode):** `register_mcp.py` auto-registers the `search_lancedb(query, top_k=10)` tool across `agy`, `grok`, `codex`, `opencode`, and existing `cursor`/`claude` configs with **zero path or scope parameters** required from the LLM:
   - **Local-First & Cross-Platform URI Decoding:** `_uri_to_local_path()` in `mcp_lancedb.py` normalizes POSIX (`file:///path`), percent-encoded (`%20`), and Windows (`file:///C:/Users/...`) `params.workspaceFolders[0].uri` paths (falling back to `AIM_WORKSPACE_ROOT` or `os.getcwd()`). If the workspace root contains `joshua_os/memory_lance`, it queries that project's isolated cartridge directly.
   - **Umbrella Subfolder & Desktop `_os_root` Fallbacks (`#94`, `#118`):** If the agent is opened in a parent/umbrella directory (excluding `$HOME` or filesystem roots) with no root `joshua_os/memory_lance`, `mcp_lancedb.py` discovers immediate child subdirectories (`*/joshua_os/memory_lance`), merges results by hybrid score, and prefixes every hit with `[Source: <subproject_name>]`. When Desktop clients such as Antigravity 2.0 omit `workspaceFolders` and launch from `$HOME` or `/`, Rule 3 falls back to the registered engine's `_os_root/memory_lance` (or `_os_root/assets/default_lance`).
   - **Dynamic Cartridge & Cache Resolution:** `retriever.py` (`get_active_aim_root()`) dynamically resolves `archive/cartridges` and `archive/flashrank_cache` relative to the active `lance_backend.LANCE_DB_PATH` (when situated inside `<project>/joshua_os/memory_lance`), ensuring supplemental `.lance` cartridges and FlashRank models are discovered in the target project even when `mcp_lancedb.py` is spawned from a central installation.
2. **Fallback (CLI-Agnostic, `#123`):** If an agent is spawned in a vessel that does not support MCP, it degrades cleanly to executing the local project launcher (`./aim search "<query>"` on POSIX; `.\aim.ps1 search "<query>"` or `.\aim.cmd search "<query>"` on Windows) or the project venv Python interpreter — never bare `python3` on Windows (`rc=9009` Microsoft Store stub).
