# Architecture

## The OS Framework
J.O.S.H.U.A. is a CLI-agnostic operating system designed to serve as the foundational brain for autonomous AI agents. The framework has entirely decoupled from legacy "CLI vessels" (e.g., aim-grok, aim-opencode). 

## Memory Synthesis & Direct-to-`main` State (#101)
The system utilizes a Just-In-Time (JIT) memory synthesis approach where Agent Memory (`memory-wiki/**` and `HANDOFF.md`) is treated as living OS state exempt from code worktree GitOps:
- The legacy `_ingest/` drop zone and background `session_summarizer.py` daemons have been abolished. 
- **Mid-Session "Save Game" (`/aim-memory-wiki`):** Conscious Agents invoke `aim-memory-wiki` synchronously to synthesize recent architectural changes into `memory-wiki/`, run `./aim index`, and push directly to `origin/main` (`git add memory-wiki/` + `git pull --rebase --autostash origin main` + `git push origin main`) with zero issues, zero worktrees, and zero prompts.
- **One-Command Closeout (`/aim-handoff`):** At session closeout, `aim-handoff` performs an **Idempotent Auto-Wiki Delta Check** on `memory-wiki/log.md` (automatically updating `memory-wiki/` first if unlogged session work occurred), surgically updates `HANDOFF.md` (`0–9` template), and pushes both `memory-wiki/` and `HANDOFF.md` to `origin/main` in a single atomic commit.
- During system boot or `./aim index`, the root `PROJECT_ROOT/memory-wiki/` and `AIM_ROOT/joshua_os_docs/` are embedded directly into the `memory_lance` LanceDB RAM pool.

### The Ingestion Engine (`bootstrap_brain.py`) & Pre-Baked `default_lance` (#101, #103–#104, #122, #130)
The primary vector ingestion engine has been hardened against configuration drift, append-only bloat, and offline vector zeroing. It recursively parses (`**/*.md` with file-path deduplication) `PROJECT_ROOT/memory-wiki/`, `PROJECT_ROOT/artifacts/AUDIT_*.md`, and `AIM_ROOT/joshua_os_docs/` to ensure zero blindspots during bootstrapping. Agents can trigger this explicitly by calling `aim index`, or ingest custom external documentation via `aim index --dir <path>`.
- **Lock-Serialized Upsert, SQL Quoting & Cached Offline Vectors (`#122`, `#130`):** `bootstrap_brain.py` assigns collision-free, repo-relative `session_id` keys via `compute_doc_session_id()`, caches existing non-zero 768-dim vectors by `(session_id, sha256)` so unchanged chunks skip re-embedding and offline Ollama runs never overwrite valid vectors with `[0.0]*768`, writes all fragments under a thread-reentrant cross-platform `.lance.lock` (`fcntl` on POSIX / `msvcrt` on Windows) in `VectorBackend.upsert_fragments()`, retains 5 minutes of manifests on live databases (`timedelta(minutes=5)`) so concurrent MCP readers never hit unlinked `.lance` files, and quotes all DataFusion SQL filter literals via `sql_quote()`.
- **Pre-Baked `default_lance` Snapshot (`56` Fragments, `v1.1.3`):** Fresh installs seed `joshua_os/memory_lance/` from `joshua_os/assets/default_lance/` (`bootstrap_brain.py --seed-default-lance`), containing the canonical `v1.1.3` `AGENTS.md` and `joshua_os_docs/` so new projects have current OS rules in their vector DB out-of-the-box.
- **Explicit `db_path` Isolation & Forward-Compatible Table Discovery (`lance_backend.py`, #104, #114 & #130):** `mcp_lancedb.py` and `retriever.perform_search(..., db_path=...)` thread `db_path` explicitly into `VectorBackend(path=db_path)` without mutating module-global `LANCE_DB_PATH`. Dead `flashrank` dependencies have been removed (`EntityIntersectionReranker` handles hybrid reranking natively). All table enumeration routes through `list_lance_tables(db)`, eliminating LanceDB deprecation warnings across modern versions.
- **Onboarding `AGENTS.md` Protection (`aim_init.py` & `BOOTSTRAP.md`):** `aim_init.provision_agents_md()` backed by `joshua_os/.aim_core/templates/default_AGENTS.md` (kept byte-for-byte identical to root `AGENTS.md`) guarantees `./aim init` (interactive or `--headless --persona <name>`) never truncates `AGENTS.md` to a stub, and `install-agent.sh` / `install-agent.ps1` (`bootstrap_install.py --mode agent`) automatically resolves specialist blueprints from `aim-coagents`.

## The Skill Library Architecture
The `aim-skill-library` utilizes a **Base + Override** architecture. All universal tool skills reside in the global `skills/` directory. However, when a specific vessel requires unique mechanics (e.g., `aim-handoff` triggering distinct `agy-blackbox` or `grok-blackbox` commands), the vessel-specific override is stored in `vessels/<cli>/skills/`. Cross-platform onboarding is handled by `scripts/install.py` (wrapped by `scripts/install.sh` on POSIX and `scripts/install.ps1` on Windows PowerShell) supporting `--mode auto|symlink|copy` with automatic directory-copy fallback when unprivileged Windows symlinks raise `OSError` (`WinError 1314`).

## TUI Cockpit (aim_config.py)
The TUI has been strictly scoped down to OS-level environment management. It no longer contains logic for modifying agent personas, modifying markdown files via regex, or toggling legacy background daemons. Its mandate is limited to:
- Secret Vault & API Key Management
- LLM Cognitive Tier Routing (RAG Model Matrix)
- MCP Server Configuration
- Archive Retention settings

## Handoff vs Reincarnation
The original `reincarnation` sub-package (which automatically spawned new terminals via background hooks) has been completely purged from the codebase. It has been 100% superseded by the `aim-handoff` skill, placing the responsibility of context teleportation back into the hands of the conscious agent rather than unpredictable background daemons.

## Tool Injection (MCP) & Multi-Harness Registration (#116)
J.O.S.H.U.A. operates with a strict "Two-Tier Protocol" for extending capabilities (such as the LanceDB memory pool).
- **Primary (Native Multi-Harness MCP via `register_mcp.py`):** During installation (`bootstrap_install.py` / `install*.sh` / `install*.ps1`), `register_mcp.py` automatically registers `search_lancedb` bound explicitly to the engine's `joshua_os/venv` Python interpreter and absolute `mcp_lancedb.py` path across detected harnesses: Antigravity (`~/.gemini/config/mcp_config.json`), Grok CLI (`~/.grok/config.toml`), Codex CLI (`~/.codex/config.toml`), OpenCode (`~/.config/opencode/opencode.json`), plus existing Cursor (`~/.cursor/mcp.json`) and Claude Code (`~/.claude.json`) configurations. If an older registration points to a deleted sandbox/worktree binary, `register_mcp.py` self-heals the entry automatically while preserving healthy custom paths.
- **Cross-Platform URI & Venv Resolution (`mcp_lancedb.py`):** `_uri_to_local_path()` normalizes POSIX (`file:///path`), percent-encoded (`%20`), and Windows drive-letter (`file:///C:/Users/...`) `workspaceFolders` URIs, and `mcp_lancedb.py` self-bootstraps `joshua_os/venv` `site-packages` if launched by a bare system Python interpreter.
- **Local-First + Umbrella Subfolder + Desktop `_os_root` Fallback (#94, #99 & #118):** When `workspace_path/joshua_os/memory_lance` exists locally (resolved from `workspaceFolders`, `AIM_WORKSPACE_ROOT`, or `os.getcwd()`), `mcp_lancedb.py` queries strictly that single project database (zero cross-project bleed). If launched in a parent/umbrella directory (excluding `$HOME` or filesystem roots via `_is_home_or_fs_root()`) with no root database, `mcp_lancedb.py` discovers immediate `*/joshua_os/memory_lance` subfolders, queries each read-only, and tags hits with `[Source: <subfolder>]`. When Desktop clients such as Antigravity 2.0 omit `workspaceFolders` and spawn `mcp_lancedb.py` from `$HOME` or `/`, Rule 3 falls back automatically to the registered engine's own `_os_root/memory_lance` (or `_os_root/assets/default_lance`). `retriever.py` (`get_active_aim_root(db_path=db_path)`) dynamically resolves supplemental `archive/cartridges` relative to the explicit `db_path` passed by `mcp_lancedb.py` (`#130`).
- **Fallback (CLI-Agnostic, #123):** To ensure 100% interoperability with non-MCP harnesses, agents degrade cleanly to `./aim search "<query>"` (POSIX), `.\aim.ps1 search "<query>"` / `.\aim.cmd search "<query>"` (Windows), or the project venv Python interpreter — never bare `python3` on Windows, which hits the Microsoft Store stub (`rc=9009`).

## Modular CLI Router (`aim_cli.py`, `cli_vault.py`, `cli_memory.py`) & Cross-Platform Support (#98, #116, #119, #124)
The CLI router (`joshua_os/.aim_core/aim_cli.py`) has been decomposed into focused domain modules while preserving top-level symbol re-exports and native Windows 10/11 + Linux/macOS/WSL execution (`aim`, `aim.ps1`, `aim.cmd`, `bootstrap_install.py`, and `config_utils.py`):
- **Tier 1 Universal Core vs. Tier 2 POSIX Swarm Boundary (#116, #123):** Tier 1 capabilities (pure-Python GitOps worktrees, LanceDB RAG + multi-harness MCP, `memory-wiki/` + `HANDOFF.md` protocols, Forensic Blackbox Vault, and GitHub Projects CLI) run identically on Windows 10/11, macOS, Linux, and WSL across any LLM harness (`SecretStorage` is gated via PEP 508 `sys_platform == 'linux'`). Tier 2 capabilities (`tmux` detached orchestration / `aim-communicate` on Linux/WSL/macOS and `bwrap` sandboxing on Linux/WSL) are explicitly POSIX-scoped in `AGENTS.md` and `default_AGENTS.md`.
- **Dual Antigravity 2.0 + Legacy CLI Path Resolution (`config_utils.py`, #119):** `get_agy_roots()`, `get_agy_brain_dirs()`, `find_agy_transcript()`, and `get_agy_settings_paths()` check Antigravity 2.0 (`~/.gemini/antigravity`) first and legacy CLI (`~/.gemini/antigravity-cli`) second across vault sealing, handoff adapters, ephemeral session cleanup, and workspace trust.
- **`aim_cli.py`**: Core pure-Python GitOps (`fix` with unborn-`HEAD` guard, `push` via `git_push_changes` syncing both `VERSION` and `joshua_os/VERSION`, `promote` with `-uno` root-clean gate & Windows shell-lock cleanup, `merge-batch`, `prune-remote`, `bug`, `projects`), RAG dispatch (`search`, `map`, `index`), diagnostics (`doctor`, `health` via `VectorBackend(path=lance_dir)`, `status`), and `update` (syncing `VERSION`, `joshua_os/VERSION`, and `BOOTSTRAP.md`).
- **`cli_vault.py`**: Forensic blackbox and Handoff vNext handlers (`cmd_vault`, `cmd_agy_blackbox`, `cmd_grok_blackbox`, `cmd_codex_blackbox`, `cmd_opencode_blackbox`, `cmd_handoff_vnext`), honoring `--vessel-root` / `--vessel` across all sealing paths (`#132`) and enforcing non-zero `sys.exit(1)` + `stderr` diagnostics on missing transcripts or encryption failures (`#119`).
- **`cli_memory.py`**: Cartridge exchange, project-scoped FTS5 session notebook (`cmd_sessions`, `cmd_search_sessions` with `_sanitize_fts5_query()` quoting hyphens/dots/`#` and exiting `1` on DB error, `#124`), session recall/audit (`cmd_audit` & `cmd_recall` propagating `rc=1` on missing/corrupt `history.db`, `#134`), and rolling archive maintenance (`cmd_clean` forwarding `[days]` and `--immediate` with `VectorBackend.compact() -> True`, `cmd_sync`, `cmd_bake`, `cmd_exchange`, `cmd_jack_in`, `cmd_unplug`, `cmd_purge`, `cmd_uninstall` pruning empty `workspace/`, `cmd_import`).
- Deprecated `swarm` CLI routes were removed from `aim_cli.py` in favor of `aim-coagents` blueprints (`install-agent.sh`) and `aim-communicate` tmux messaging.
