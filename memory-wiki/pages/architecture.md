# Architecture

## The OS Framework
J.O.S.H.U.A. is a CLI-agnostic operating system designed to serve as the foundational brain for autonomous AI agents. The framework has entirely decoupled from legacy "CLI vessels" (e.g., aim-grok, aim-opencode). 

## Memory Synthesis & Direct-to-`main` State (#101)
The system utilizes a Just-In-Time (JIT) memory synthesis approach where Agent Memory (`memory-wiki/**` and `HANDOFF.md`) is treated as living OS state exempt from code worktree GitOps:
- The legacy `_ingest/` drop zone and background `session_summarizer.py` daemons have been abolished. 
- **Mid-Session "Save Game" (`/aim-memory-wiki`):** Conscious Agents invoke `aim-memory-wiki` synchronously to synthesize recent architectural changes into `memory-wiki/`, run `./aim index`, and push directly to `origin/main` (`git add memory-wiki/` + `git pull --rebase --autostash origin main` + `git push origin main`) with zero issues, zero worktrees, and zero prompts.
- **One-Command Closeout (`/aim-handoff`):** At session closeout, `aim-handoff` performs an **Idempotent Auto-Wiki Delta Check** on `memory-wiki/log.md` (automatically updating `memory-wiki/` first if unlogged session work occurred), surgically updates `HANDOFF.md` (`0–9` template), and pushes both `memory-wiki/` and `HANDOFF.md` to `origin/main` in a single atomic commit.
- During system boot or `./aim index`, the root `PROJECT_ROOT/memory-wiki/` and `AIM_ROOT/joshua_os_docs/` are embedded directly into the `memory_lance` LanceDB RAM pool.

### The Ingestion Engine (`bootstrap_brain.py`) & Pre-Baked `default_lance` (#101, #103–#104)
The primary vector ingestion engine has been hardened against configuration drift. It recursively parses (`**/*.md` with file-path deduplication) both the root `PROJECT_ROOT/memory-wiki/` and `AIM_ROOT/joshua_os_docs/` trees to ensure zero blindspots during bootstrapping. Agents can trigger this explicitly by calling `aim index`, or ingest custom external documentation via `aim index --dir <path>`.
- **Pre-Baked `default_lance` Snapshot (`60` Fragments, `v1.0.0`):** Fresh `curl` installs seed `joshua_os/memory_lance/` from `joshua_os/assets/default_lance/`, which is built in a single atomic transaction containing the canonical `AGENTS.md` (including Direct-to-`main` memory exemption and `Spoken Summary (🔊)` Neural TTS rules) and `joshua_os_docs/` so new projects have `v1.0.0` OS rules in their vector DB out-of-the-box.
- **Dynamic `LANCE_DB_PATH` & Forward-Compatible Table Discovery (`lance_backend.py`, #104 & #114):** `VectorBackend.__init__(self, path=None)` resolves `self.path = path or LANCE_DB_PATH` at instantiation time rather than import time so runtime overrides from `mcp_lancedb.py` take effect immediately. All table enumeration across `lance_backend.py`, `retriever.py`, and `joshua_os/handoff/embed_store.py` routes through `list_lance_tables(db)`, which calls `db.list_tables()` and unwraps `ListTablesResponse.tables` (falling back cleanly to iterables or legacy `db.table_names()`), eliminating LanceDB deprecation warnings across modern versions.
- **Onboarding `AGENTS.md` Protection (`aim_init.py` & `BOOTSTRAP.md`):** `aim_init.provision_agents_md()` backed by `joshua_os/.aim_core/templates/default_AGENTS.md` guarantees `./aim init` (interactive or `--headless --persona <name>`) never truncates `AGENTS.md` to a stub, and `install-agent.sh [persona]` automatically resolves specialist blueprints from `aim-coagents`.

## The Skill Library Architecture
The `aim-skill-library` utilizes a **Base + Override** architecture. All universal tool skills reside in the global `skills/` directory. However, when a specific vessel requires unique mechanics (e.g., `aim-handoff` triggering distinct `agy-blackbox` or `grok-blackbox` commands), the vessel-specific override is stored in `vessels/<cli>/skills/`. Cross-platform onboarding is handled by `scripts/install.py` (wrapped by `scripts/install.sh` on POSIX and `scripts/install.ps1` on Windows PowerShell) supporting `--mode auto|symlink|copy` with automatic directory-copy fallback when unprivileged Windows symlinks raise `OSError` (`WinError 1314`).

## TUI Cockpit (aim_config.py)
The TUI has been strictly scoped down to OS-level environment management. It no longer contains logic for modifying agent personas, modifying markdown files via regex, or toggling legacy background daemons. Its mandate is limited to:
- Secret Vault & API Key Management
- LLM Cognitive Tier Routing (RAG Model Matrix)
- MCP Server Configuration
- Archive Retention settings

## Handoff vs Reincarnation
The original `reincarnation` sub-package (which automatically spawned new terminals via background hooks) has been completely purged from the codebase. It has been 100% superseded by the `aim-handoff` skill, placing the responsibility of context teleportation back into the hands of the conscious agent rather than unpredictable background daemons.

## Tool Injection (MCP) & Multi-Harness Registration (#116)
J.O.S.H.U.A. operates with a strict "Two-Tier Protocol" for extending capabilities (such as the LanceDB memory pool).
- **Primary (Native Multi-Harness MCP via `register_mcp.py`):** During installation (`bootstrap_install.py` / `install*.sh` / `install*.ps1`), `register_mcp.py` automatically registers `search_lancedb` bound explicitly to the engine's `joshua_os/venv` Python interpreter and absolute `mcp_lancedb.py` path across detected harnesses: Antigravity (`~/.gemini/config/mcp_config.json`), Grok CLI (`~/.grok/config.toml`), Codex CLI (`~/.codex/config.toml`), OpenCode (`~/.config/opencode/opencode.json`), plus existing Cursor (`~/.cursor/mcp.json`) and Claude Code (`~/.claude.json`) configurations. If an older registration points to a deleted sandbox/worktree binary, `register_mcp.py` self-heals the entry automatically while preserving healthy custom paths.
- **Cross-Platform URI & Venv Resolution (`mcp_lancedb.py`):** `_uri_to_local_path()` normalizes POSIX (`file:///path`), percent-encoded (`%20`), and Windows drive-letter (`file:///C:/Users/...`) `workspaceFolders` URIs, and `mcp_lancedb.py` self-bootstraps `joshua_os/venv` `site-packages` if launched by a bare system Python interpreter.
- **Local-First + Umbrella Subfolder Fallback (#94 & #99):** When `workspace_path/joshua_os/memory_lance` exists locally, `mcp_lancedb.py` queries strictly that single project database (zero cross-project bleed). If the CLI is launched in a parent/umbrella directory (e.g., `~/aim-agents/`) with no root database, `mcp_lancedb.py` automatically discovers immediate `*/joshua_os/memory_lance` subfolders, queries each read-only, tags hits with `[<subfolder>]`, and returns the top-K results by score without adding parameters to the MCP tool signature. `retriever.py` dynamically resolves `archive/cartridges` and `archive/flashrank_cache` from `lance_backend.LANCE_DB_PATH` (`get_active_aim_root()`) so Sandwich Context Expansion and Datajack cartridges track the active child project.
- **Fallback (CLI-Agnostic):** To ensure 100% interoperability with legacy or custom CLI loops, agents gracefully degrade to direct python subprocess shell commands (e.g., `aim_cli.py search`) if an MCP tool is not present in their prompt. This guarantees no agent is ever completely blind.

## Modular CLI Router (`aim_cli.py`, `cli_vault.py`, `cli_memory.py`) & Cross-Platform Support (#98, #116)
The CLI router (`joshua_os/.aim_core/aim_cli.py`) has been decomposed into focused domain modules while preserving top-level symbol re-exports and native Windows 10/11 + Linux/macOS/WSL execution (`aim`, `aim.ps1`, `aim.cmd`, `bootstrap_install.py`, and `resolve_venv_python` in `config_utils.py`):
- **Tier 1 Universal Core vs. Tier 2 POSIX Swarm Boundary (#116):** Tier 1 capabilities (pure-Python GitOps worktrees, LanceDB RAG + multi-harness MCP, `memory-wiki/` + `HANDOFF.md` protocols, Forensic Blackbox Vault, and GitHub Projects CLI) run identically on Windows 10/11, macOS, Linux, and WSL across any LLM harness (`SecretStorage` is gated via PEP 508 `sys_platform == 'linux'`). Tier 2 capabilities (`tmux` detached orchestration / `aim-communicate` on Linux/WSL/macOS and `bwrap` sandboxing on Linux/WSL) remain strictly POSIX-scoped rather than emulating multiplexers on native Windows.
- **`aim_cli.py`**: Core pure-Python GitOps (`fix`, `push` via `git_push_changes` with `--include-untracked` / `-a`, `promote`, `merge-batch`, `prune-remote`, `bug`, `projects`), RAG dispatch (`search`, `map`, `index`), diagnostics (`doctor`, `health`, `status`), and `update`.
- **`cli_vault.py`**: Forensic blackbox and Handoff vNext handlers (`cmd_vault`, `cmd_agy_blackbox`, `cmd_grok_blackbox`, `cmd_codex_blackbox`, `cmd_opencode_blackbox`, `cmd_handoff_vnext`).
- **`cli_memory.py`**: Cartridge exchange, project-scoped FTS5 session notebook (`cmd_sessions`, `cmd_search_sessions`), session recall/audit, and rolling archive maintenance (`cmd_clean`, `cmd_sync`, `cmd_audit`, `cmd_recall`, `cmd_bake`, `cmd_exchange`, `cmd_jack_in`, `cmd_unplug`, `cmd_purge`, `cmd_uninstall`, `cmd_import`).
- Deprecated `swarm` CLI routes were removed from `aim_cli.py` in favor of `aim-coagents` blueprints (`install-agent.sh`) and `aim-communicate` tmux messaging.
